
Практична 4

1. Навіщо в програмуванні окремий тип для «так» і «ні»?
Булевий тип даних (Boolean) потрібен для керування логікою та напрямком роботи програми. Комп'ютеру постійно доводиться ухвалювати рішення: «користувач ввів правильний пароль?», «чи закінчилися товари на складі?», «чи увімкнені сповіщення?». Булевий тип має лише два значення: True (істина / так) та False (хибність / ні). 

Якби ми замість цього використовували звичайні числа (наприклад, 1 та 0) або текст ("так" і "ні"), це призвело б до помилок. Хтось міг би випадково записати туди число 5 або слово "yes", і комп'ютер не знав би, як на це реагувати. Окремий тип гарантує, що у логічному виразі завжди буде лише два чітких варіанти, що робить код надійним і швидким.

2. Як сказати !(a && b) людською мовою?
За логічним законом де Моргана, вираз !(a && b) (НЕ(а І b)) еквівалентний виразу !a || !b (НЕ а АБО НЕ b). 

Людською мовою це означає: «Хтось один точно відсутній» або «Принаймні одна з умов не виконана».
Наприклад, нехай a — це наявність грошей, а b — наявність вільного часу.
* a && b означає: «У мене є і гроші, і час» (я можу піти в кіно).
* !(a && b) означає: «У мене немає поєднання грошей та часу» (тобто або у мене немає грошей, або немає часу, або немає ні того, ні іншого — у кіно я не йду).

3. Чим && відрізняється від &?
Обидва оператори виконують логічне «І» (AND), але працюють вони абсолютно по-різному:
* && — це логічне «І» з коротким замиканням (short-circuit). Воно обчислює вирази зліва направо і зупиняється, як тільки результат стає очевидним. Якщо перша умова False, комп'ютер навіть не дивиться на другу умову, адже для «І» вся фраза вже автоматично стає брехнею. Це економить час процесора.
* & — це побітове або повне «І». Воно завжди обчислює обидві частини виразу, незалежно від того, що вийшло в першій. Також воно використовується для математичних операцій безпосередньо над бітами числа (одиницями й нулями всередині пам'яті).

 4. Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?
Завдяки згаданому вище правилу «короткого замикання» оператора &&. Коли комп'ютер бачить вираз з &&, він обчислює його покроково:
1. Спочатку він перевіряє першу частину: x != null.
2. Оскільки x порожній (null), ця умова повертає False.
3. Комп'ютер знає, що для оператора && (І) загальний результат уже буде False, якщо хоч одна частина брехлива.
4. Тому він просто ігнорує і не виконує другу частину виразу (x.name == "Іван").

Програма не намагається прочитати ім'я з порожнього об'єкта, тому критична помилка (Crash / NullPointerException) не виникає. Якби ви написали одинарний оператор &, програма спробувала б обчислити обидві частини й миттєво б упала.

5. Як запхати 32 відповіді «так/ні» в одне число?
За допомогою техніки, яка називається «бітові маски» (bitmask). Звичайне 32-бітне ціле число (наприклад, тип int) складається всередині пам'яті з 32 окремих транзисторів, кожен з яких є або 0, або 1. Оскільки 0 і 1 ідеально відповідають булевим False та True, ми можемо призначити кожен біт числа для відповіді на конкретне запитання.

Наприклад:
* 1-й біт: користувач підтвердив пошту? (1 — так, 0 — ні)
* 2-й біт: користувач преміум? (1 — так, 0 — ні)
* 3-й біт: чи увімкнено нічний режим? (1 — так, 0 — ні)
За допомогою побітових операцій (на кшталт &, |, <<) програмісти можуть швидко перевіряти або змінювати окремі прапорці (біти) всередині цього єдиного числа. Це колосально економить пам'ять та мережевий трафік у великих системах.

6. Що швидше: n % 2 чи n & 1?
Операція n & 1 працює швидше (хоча сучасні компілятори вміють це оптимізувати).
* n % 2 (залишок від ділення на 2): вимагає від процесора виконання математичної операції ділення. Ділення — це одна з найповільніших та найважчих операцій для транзисторів процесора.
* n & 1 (побітове «І» з одиницею): комп'ютер просто дивиться на найостанніший біт числа з правого боку. Якщо число парне, цей біт завжди 0, якщо непарне — завжди 1. Перевірка одного біта (& 1) виконується процесором за один такт (миттєво).
